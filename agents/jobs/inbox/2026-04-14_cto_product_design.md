## 自動X投稿パイプライン — アーキテクチャ設計案

### 全体フロー

```
[ユーザー登録・初期設定]
        ↓
  過去ツイート取得 → 文体・トンマナ学習（Claude API）
        ↓
━━━━━━ 毎日の自動サイクル ━━━━━━
        ↓
[1] トレンド取得
    X API → 今日のトレンドワード抽出
        ↓
[2] コンテンツ生成
    Claude API（Haiku）→ ユーザーの文体でドラフト生成
    ・トレンド活用ツイート: 1本
    ・教育/共感系ツイート: 2本
    合計: 1日3本生成
        ↓
[3] 承認フロー（Starter以上）
    通知 → ユーザーが確認 → 承認 or 修正 or 却下
    Pro以上: 承認不要（フル自動）オプション
        ↓
[4] 最適時間に自動投稿
    X API POST → 7:00 / 12:00 / 21:00（ユーザー設定可）
        ↓
[5] エンゲージメント計測
    X API GET → いいね/RT/インプ/フォロワー増減を記録
        ↓
[6] 週次レポート生成
    Claude API → 「今週何が効いたか」を自然言語で解説
━━━━━━━━━━━━━━━━━━━━━━━━
```

## 技術スタック（推奨）

| レイヤー | 技術 | 理由 |
|---------|------|------|
| バックエンド | Python + FastAPI | AI連携が最もやりやすい |
| タスクスケジューラ | Celery + Redis | 投稿時間の精度管理 |
| データベース | PostgreSQL | ユーザーデータ・投稿履歴 |
| AI | Claude API (Haiku 4.5) | コスト最安、生成品質十分 |
| SNS連携 | X API v2 | 公式API（pay-per-use） |
| ホスティング | Railway or Render | 小規模スタートに最適、安価 |
| 認証 | Supabase Auth | 実装コスト最小 |
| 決済 | Stripe | サブスク管理の定番 |

---

## ユーザーの"声"を学習する仕組み

1. **初回セットアップ時**に過去100ツイートをX APIで取得
2. Claudeに「この人の文体の特徴を10点で整理して」とプロンプト
3. 生成されたペルソナサマリーをDBに保存
4. 以降の生成時は毎回このサマリーをシステムプロンプトに注入
5. 投稿後のエンゲージメントを見て定期的にサマリーを更新（学習ループ）

## 技術リスク

| リスク | 影響度 | 対策 |
|--------|--------|------|
| X API料金高騰 | 高 | pay-per-useで使用量をユーザー別に上限管理 |
| Xアカウント凍結（自動投稿検知） | 高 | 投稿間隔をランダム化、人間らしい文体を維持 |
| Claude APIのレイテンシ | 中 | Batch APIで非同期処理 |
| スケール時のコスト増 | 中 | Haikuモデル＋キャッシュで抑制 |

---

**CTOより**: MVP開発に着手する前に、Jobs・CFOと原価確認を済ませることを推奨。
X APIのpay-per-use料金次第でアーキテクチャの変更が必要になる可能性あり。
