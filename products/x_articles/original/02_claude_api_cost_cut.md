## 「APIが高い」は設計の問題

Claude APIを使い始めた頃、月のAPI費用が思ったより膨らんでいた。

毎回同じシステムプロンプトを送っているのに、そのたびにトークン料金が発生している。同じ文脈を何度もAPIに送り続けているのは、電気をつけたまま外出するのと同じだと気づいた。

コスト削減は「安いモデルを使う」だけではない。**設計を変えることで同じモデルを使いながら費用を大幅に減らせる。**

この記事では、実際に使って効果が出た4つの方法をまとめる。

---

## 方法1: プロンプトキャッシュ（最大90%削減）

**仕組み**

同じプロンプトの先頭部分（システムプロンプトや固定コンテキスト）をAnthropicのサーバーにキャッシュし、2回目以降は再送信せずにキャッシュを参照する。

**料金の差**

| トークン種別 | 通常料金 | キャッシュ読み出し |
|------------|---------|-----------------|
| 入力 | 100% | 10%（90%引き） |
| キャッシュ書き込み | — | 125% |

キャッシュの書き込みコストはやや高いが、同じプロンプトを2回以上使えばすぐに元が取れる。

**実装方法**

```python
import anthropic

client = anthropic.Anthropic()

# システムプロンプトをキャッシュする
response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=1024,
    system=[
        {
            "type": "text",
            "text": "あなたはAxeonのX投稿担当AIです。...(長いシステムプロンプト)...",
            "cache_control": {"type": "ephemeral"}  # ここでキャッシュを指定
        }
    ],
    messages=[{"role": "user", "content": "今日の投稿を作成してください"}]
)
```

`cache_control: {"type": "ephemeral"}` をつけるだけで有効になる。キャッシュの有効期限は5分。

**自動投稿システムへの応用**

毎回同じシステムプロンプト（アカウントのペルソナ設定・投稿ルール等）を送っているなら、プロンプトキャッシュの効果が最も大きい。

## 方法2: Batch API（50%削減）

**仕組み**

すぐに結果が必要ない処理をまとめてバッチ送信すると、通常料金の50%で実行できる。

**向いている用途**

- 記事の一括生成
- 複数商材の投稿文を事前生成してストック
- ログデータの一括分析

**実装**

```python
import anthropic

client = anthropic.Anthropic()

# バッチリクエストを作成
batch = client.messages.batches.create(
    requests=[
        {
            "custom_id": "post_1",
            "params": {
                "model": "claude-haiku-4-5-20251001",
                "max_tokens": 300,
                "messages": [{"role": "user", "content": "ahamo光の投稿文を作成"}]
            }
        },
        {
            "custom_id": "post_2",
            "params": {
                "model": "claude-haiku-4-5-20251001",
                "max_tokens": 300,
                "messages": [{"role": "user", "content": "auひかりの投稿文を作成"}]
            }
        }
    ]
)
```

結果は非同期で返ってくる（最大24時間）。リアルタイム不要な処理に限定して使う。

## 方法3: モデル選択の最適化

用途に対してオーバースペックなモデルを使っていることが、コスト増の原因になりやすい。

| モデル | 入力コスト | 向いている用途 |
|--------|-----------|--------------|
| Haiku 4.5 | 最安 | 投稿文生成・分類・簡単な要約 |
| Sonnet 4.6 | 中間 | 記事生成・複雑な指示への対応 |
| Opus 4.7 | 最高 | 高度な推論・複雑な長文生成 |

自動投稿システムの投稿文生成程度であればHaikuで十分だ。Opusはよほど複雑な処理の時だけ使う。

**ルーティングの実装例**

```python
def select_model(task_type: str) -> str:
    if task_type == "simple_post":
        return "claude-haiku-4-5-20251001"
    elif task_type == "article":
        return "claude-sonnet-4-6"
    else:
        return "claude-opus-4-7"
```

タスクの種類でモデルを自動選択する設計にすると、コストと品質のバランスが最適化される。

## 方法4: トークン最適化

同じ出力品質でもプロンプトの書き方次第でトークン数は変わる。

**不要な丁寧さを省く**

```
# 悪い例（トークン無駄）
あなたは優秀なライターです。以下の内容について、読者にとってわかりやすく、
かつ魅力的な文章でXの投稿文を作成してください。文字数は100字程度でお願いします。

# 良い例（最小限）
X投稿文を100字で作成。テーマ: ahamo光の節約効果。体験談形式。
```

指示を短くしても出力品質はほぼ変わらない。

**max_tokensを適切に設定する**

デフォルト値が大きいまま使っていると、実際には不要なトークンに課金されることがある。出力の最大長を用途に合わせて設定する。

## 4つを組み合わせた場合の効果

月100回のAPI呼び出しで、1回あたり2,000トークン入力・300トークン出力と仮定した場合（Sonnet使用）：

| 設計 | 月額コスト目安 |
|-----|-------------|
| 最適化なし | 約$3〜5 |
| モデルをHaikuに変更 | 約$0.5〜1 |
| + プロンプトキャッシュ | 約$0.1〜0.3 |
| + Batch API | 約$0.05〜0.15 |

4つすべて適用すると、元のコストから**90%以上削減**できるケースがある。

---

## 自動投稿システムへの適用順序

効果が大きい順に適用するのが効率的だ：

1. **プロンプトキャッシュ** — 最も効果が大きく、コード変更が小さい
2. **モデル選択** — タスクに合ったモデルへの切り替え
3. **Batch API** — リアルタイム不要な処理を分離
4. **トークン最適化** — プロンプトのリファクタリング
